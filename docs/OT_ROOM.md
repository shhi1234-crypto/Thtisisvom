# VOM Company 2 — OT Room 적용안

운영진이 가입 인사 댓글에 개별 등록 링크를 안내하고, 신규 가입자는 이름·소모임 닉네임·인증 영상을 제출한다. 운영진은 기존 관리자 계정 또는 별도로 확인된 운영진 개인 계정으로 심사한다. 기존 회원·공연·셋리스트 데이터와 정책은 이 변경에서 수정하지 않는다.

## 구현된 동작

| 항목 | 동작 |
| --- | --- |
| 등록 페이지 | `/ot-room/#token=…` — 홈페이지 메뉴·회원 정보·영상 조회 기능 없음 |
| 운영진 페이지 | `/ot-admin/` — 기존 운영자료 페이지와 메뉴에 연결 |
| 등록 시간 | 한국시간 09:00 이상, 18:00 미만. 업로드 시작·완료와 DB 등록 시 검사 |
| 안내 | 당일 처리 보장 없음, 익일 안내 가능 |
| 제출 정보 | 이름, 소모임 닉네임, 영상, 가입 확인 목적의 검토 동의 |
| 등록 링크 | 건별 256비트 난수, DB에는 SHA-256 해시만 저장, 7일 유효·1회 등록·운영진 중지 가능 |
| 영상 | 기존 `ot-review-videos` 비공개 버킷, 최대 50MB, MP4/MOV/WEBM/3GP |
| 심사 | 기존 `ot_reviews`·`ot_review_votes` 재사용, 제출 당시 활동 운영진 과반 기준 유지 |
| 심사 목표 | 기존 2시간 목표 유지. 시간이 지나도 자동 반려되지 않음 |
| 최종 가입 | 심사 승인 후 기존 MEMBERS에 등록한 회원과 관리자가 연결. 승인 투표가 회원 계정을 자동 생성하지 않음 |
| 푸시 | 기존 VAPID·알림 구독 재사용. 실제 등록 완료 뒤 발송, 실패 시 재시도 상태 저장 |
| 재시도 | 기존 `admin-reminder-push` 크론 호출 시 대기 OT 알림 처리. 운영진 화면의 수동 재시도도 제공 |

새 OT 제출은 함수 메모리와 업로드 시간을 고려해 50MB로 제한한다. 기존 버킷의 100MB 설정과 이전 관리자 자료 재생 제한은 변경하지 않는다.

등록 링크의 토큰은 URL fragment에서 읽어 같은 탭의 sessionStorage로 옮기고 주소에서 지운다. 링크·페이지·API에 `no-referrer`와 `no-store`를 적용한다. 등록에 실패하면 Storage API로 미등록 파일을 정리하고, DB 등록 성공 여부가 불확실할 때는 등록 상태를 다시 확인해 이미 제출된 영상을 삭제하지 않는다.

## 접근 권한

| 사용자 | 자기 등록 상태 | 영상·심사 목록 | 심사 의견 | 최종 가입 연결·OT 권한 관리 |
| --- | --- | --- | --- | --- |
| 유효한 개별 링크 보유자 | 가능 | 불가 | 불가 | 불가 |
| 일반 회원 / 가입 대기자 | 링크 보유 시만 | 불가 | 불가 | 불가 |
| OT 권한을 확인한 활동 운영진 | 가능 | 가능 | 본인 명의 | 불가 |
| 기존 관리자 | 가능 | 가능 | 기존 운영진 대리 기록 유지, 관리자 UID 감사 기록 | 가능 |

`role='운영진'`만으로 OT 열람 권한을 부여하지 않는다. 현재 사이트는 공통 초기 비밀번호 `0000`으로 미연결 회원의 개인 계정을 설정할 수 있기 때문이다. `ot_room_operator_access`를 별도로 두고, 적용 당시 이미 연결된 활동 운영진만 보존한다. 이후 신규 연결·재연결 계정은 관리자가 본인 여부를 확인하고 권한을 부여한다. 기존 `admins` 관리자 권한을 일반 운영진으로 확대하지 않는다.

가입자는 영상 재생 URL을 받지 않는다. 운영진도 매 요청마다 Auth JWT와 현재 권한을 검증받고 영상 바이트를 받아 브라우저 내부 Blob URL로 재생한다. 목록 API는 저장 경로·서명 URL·등록 토큰 해시를 반환하지 않는다. 기존 관리자 Storage 정책은 이전 관리자 작업을 손상하지 않도록 유지한다. 따라서 신뢰된 관리자가 별도 도구에서 링크를 만들거나, 권한 있는 사람이 영상을 복사·촬영하는 행위까지 차단하는 구조는 아니다.

## 홈페이지 전체 정보 비공개 전환은 별도 단계

현재 확인된 운영 데이터: 회원 41명, 개인 계정 연결 7명, 활동 운영진 7명 중 연결 4명. 기존 `members`, `events`, 일부 셋리스트 조회는 `anon`에게 열려 있고, 저장소도 공개 상태다. **OT 영상 비공개 구현이 홈페이지 전체 정보 비공개를 의미하지 않는다.**

전체 비공개 전환에는 아래 작업이 먼저 필요하다.

1. 공통 `0000` 최초 설정을 관리자 발급 개인 활성화 코드 또는 확인된 가입 초대로 교체한다. 미설정 기존 회원의 설정 방법도 함께 준비한다.
2. 기존 MY VOM 로그인 화면의 공개 회원 목록을 대체하고, 회원 전용 화면에서 로그인·활동 회원 여부를 검사한다.
3. `members`·일정·셋리스트에 서버와 RLS의 회원 조회 제한을 적용한다. `SECURITY DEFINER` 랭킹 뷰도 함께 점검하고 보호한다.
4. 서비스 권한으로 모든 일정을 반환하는 기존 `public-events`를 비공개 대상과 분리한다. CORS만으로 외부 접근을 막을 수는 없다.
5. 공개 저장소·HTML·공개 이미지에 들어 있는 내부 정보를 점검한다. 브라우저에서 메뉴를 감추는 방식만으로 정적 파일을 보호할 수는 없다.
6. 관리자·기존 회원·가입 대기자·외부 사용자의 읽기/수정 권한을 다시 검증한 뒤 단계적으로 전환한다.

이 전체 전환을 OT 추가 마이그레이션과 함께 즉시 적용하지 않으므로, 기존 로그인·회원·공연 기능을 갑자기 차단하지 않는다. OT 링크를 배포할 때에도 홈페이지 전체가 이미 비공개로 전환됐다고 안내하면 안 된다.

## 수정 파일

| 파일 | 목적 |

| `supabase/functions/ot-review/index.ts` | 운영진 인증·영상 재생·심사·최종 가입 연결 |

`ot-review`와 `admin-reminder-push` 소스는 GitHub에 없던 현재 배포 코드를 확인해 가져온 뒤 수정했다. 기존 `member-account` 함수는 변경하지 않는다.

## 적용 순서와 검증

1. 추가 마이그레이션을 검토한 뒤 DB에 적용한다. 기존 버킷이 이미 비공개일 때만 성공하며, 기존 회원·일정 데이터를 쓰거나 삭제하지 않는다.
2. `ot-room`, `ot-review`, `admin-reminder-push`를 `_shared` 의존 파일과 함께 배포한다. `verify_jwt=false`는 인증 생략이 아니라 개별 초대/검증된 Auth JWT/기존 크론 secret을 서버에서 확인하는 설정이다.
3. 프론트엔드 변경을 main에 반영하고 기존 Vercel 배포에서 새 페이지와 메뉴를 확인한다.
4. 실제 운영진 계정에서 링크 발급·권한·영상 검토를 확인하고, 승인과 최종 가입 안내를 구분한다. 테스트 푸시는 다른 운영진에게 임의 발송하지 않는다.

이 PR은 추가 구현과 적용 파일을 준비한 결과이며, 실제 배포 여부는 별도의 적용 기록으로 구분해야 한다. 추가 DB 필드는 프론트엔드 롤백 시 유지해도 기존 기능에 영향을 주지 않는다. 함수 롤백은 이전 배포 버전을 사용하고, 새 등록 링크는 중지한다. 회원/영상 데이터 삭제를 롤백 수단으로 사용하지 않는다.

검증은 Deno 2.9.6 및 PostgreSQL 17 기반 PGlite 0.5.8의 로컬 테스트로 수행한다. 서버 함수 타입 검사, KST 경계, 초대 만료·회수·재사용, 중복 업로드, 등록 실패 정리, 일반 회원·미확인 운영진의 접근 거부, 서명 URL 미반환, 대리 투표 감사 기록, 과반 확정 및 RPC 권한을 확인한다. PostgreSQL 테스트는 실제 마이그레이션을 먼저 설치한 뒤 테스트용 시계만 주입해 시간 경계를 재현한다. 실제 운영 서비스의 가입 처리나 푸시 발송을 실행하는 테스트는 아니다.

검증 결과: 서버 동작 테스트 17개, PostgreSQL 마이그레이션·권한 검사 29개, 브라우저 화면·동작 검사 20개 통과. 브라우저 검사는 서버 응답을 가짜 데이터로 대체해 PC/모바일 제출, 18시 버튼 차단, 로그인 전 화면 차단, 인증 영상 Blob 재생·종료, 링크 발급, 입력값 HTML 이스케이프와 가로 넘침을 확인했다. 실제 배포 환경의 네트워크·영상 전송은 적용 후 별도로 확인해야 한다. 기존 화면의 변경된 스크립트 구문과 Git diff 공백 검사도 통과했다.

npm ci --prefix tests/runtime
ln -s tests/runtime/node_modules node_modules
