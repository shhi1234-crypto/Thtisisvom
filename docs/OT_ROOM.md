# OT Room 운영 및 배포

2026-10-07 확정: 멤버스(`/members/`)와 스케줄(`/calendar/`, `/schedule/`)은 승인된 회원 및 관리자만 이용한다. 나머지 기존 화면은 공개로 둘러볼 수 있다. 새 홍보·공연 페이지는 만들지 않는다. 기존 회원·공연·셋리스트 행을 덮어쓰거나 삭제하지 않는다.

## 가입 흐름

소모임 가입 인사 → 운영진의 개별 OT 링크 안내 → 본인 아이디·개인 비밀번호 설정 및 가입 정보 입력 → 인증 영상 등록 → 운영진 과반 승인 → 같은 계정에 연결된 회원 프로필 자동 생성.

아이디는 영문·숫자·._- 조합 4~30자, 신규 비밀번호는 8~64자다. 비밀번호는 Supabase Auth에서만 처리한다. 이름·소모임 닉네임은 필수이며 연락처·생년월일·지역·성별은 선택이다. 수집·이용 동의 시점과 안내 버전을 기록한다. 실명과 연락처 등 신청 개인정보는 `ot_room_applicants`에 보관한다. 회원 표시 이름은 소모임 닉네임이며, 동일 닉네임 충돌 시 구분값을 붙인다.

개별 링크는 256비트 난수, DB에는 해시만 저장한다. 7일 유효, 운영진이 중지할 수 있다. 계정 설정 후에는 링크만 가진 사람이 신청 현황·개인정보를 볼 수 없으며 본인 계정으로 로그인해야 한다. 링크 없이 OT Room에 접속해도 개인 계정으로 신청 상태를 확인할 수 있다.

영상 등록은 한국시간 09:00 이상, 18:00 미만이다. 업로드 시작·완료와 DB 등록 시각을 각각 검사하므로 18시 전에 전송과 등록을 마쳐야 한다. 당일 처리 보장 없이 익일 안내될 수 있다는 문구를 표시한다. 기존 2시간 검토 목표는 유지하되 시간 경과만으로 자동 반려하지 않는다.

기존 `ot_reviews`, `ot_review_votes`의 과반 판정을 재사용한다. 제출 당시 활동 운영진을 기준으로 과반수를 정하며 중복 투표는 한 사람의 의견 수정으로 처리한다. 승인 판정과 회원 생성은 같은 DB 트랜잭션이다. 재시도해도 프로필은 한 번만 생성되며 가입 신청자의 JWT나 메타데이터로 회원·운영진 권한을 설정할 수 없다. 이전 관리자 수동 등록 건의 회원 연결 기능은 유지한다.

## 개인정보 및 영상 권한

| 정보 | 접근 |
| --- | --- |
| 공개 화면의 표시 이름·사진·공개 활동 정보 | 기존 공개 화면 이용자 |
| 멤버스 및 내부 스케줄 | 승인된 활동 회원, 관리자 |
| 연락처·생년월일·지역·성별 등 개인정보 | 본인, 권한 있는 관리자/가입 검토 운영진 |
| 가입 영상·심사 목록 | 본인 확인 후 OT 권한을 부여받은 활동 운영진, 기존 관리자 |
| 비밀번호 | Auth에서만 처리, 프로필·운영진 화면에 저장하거나 반환하지 않음 |

회원 공용 디렉터리 `members_public`은 본인 및 관리자 외의 개인정보 필드를 비운다. `members` 직접 조회는 본인 행 또는 기존 관리자 권한으로 제한한다. `events` 원본은 승인 회원만 읽는다. 다른 공개 화면은 기존 활동에 필요한 표시 이름 및 VOM LIVE/BUSKING/기존 OPEN MIC 정보만 읽는 `members_display`, `events_public` 투영을 사용하며 내부 OTHER 일정과 내부 OTHER 일정의 설명·메모는 반환하지 않는다. 공개 활동의 기존 주최자 안내는 유지한다. 공개 화면의 이름·활동 정보까지 비공개라고 안내하면 안 된다.

화면의 로그인 안내와 별도로 DB RLS와 서버 JWT 검증을 적용한다. 개인 비밀번호가 유출되면 그 계정의 본인 정보 및 열람 가능한 회원 공용 자료가 노출될 수 있으나 다른 회원의 개인정보를 읽거나 수정하는 권한은 얻지 못한다.

영상은 기존 비공개 `ot-review-videos` 버킷에 저장한다. 새 제출은 50MB 이하 MP4/MOV/WEBM/3GP만 허용하며 파일 앞부분도 검사한다. 일반 회원·가입자는 영상 읽기 및 Storage URL 발급 권한이 없다. 운영진 화면은 요청마다 현재 권한을 확인한 후 영상 바이트를 받아 브라우저 Blob URL로 재생한다. API는 공개/서명 Storage URL을 반환하지 않는다. 기존 신뢰된 관리자 Storage 정책은 유지한다. 권한 있는 운영진의 복사·촬영까지 막는 구조는 아니다.

## 기존 회원과 운영진

기존 개인 비밀번호를 설정한 회원은 MY VOM에서 등록된 이름과 기존 비밀번호로 로그인한다. 신규 회원은 가입 아이디로 로그인한다. 공개 회원 선택 목록과 공통 `0000` 최초 설정을 제거했다.

최초 개인 설정 또는 비밀번호 분실 시 관리자가 멤버스 편집 화면의 **개인 설정 링크 발급**을 눌러 7일 유효·한 번 사용 가능한 링크를 발급하고 본인에게만 전달한다. 발급 자체는 기존 비밀번호를 바꾸지 않으며 본인이 새 비밀번호를 설정해야 적용된다. 새로운 링크를 발급하면 이전 미사용 링크는 중지된다.

기존 관리자는 `/ot-admin/`에서 바로 검토할 수 있다. 운영진 개인 계정은 관리자 본인 확인 후 화면에서 **권한 부여**해야 한다. 기존 운영진 역할을 근거로 OT 영상 권한을 자동 부여하지 않는다. 운영진 투표는 본인 명의이며 기존 관리자 대리 기록에는 관리자 UID를 감사 기록으로 남긴다.

## 알림

정상 영상 등록 완료 시 기존 운영진 웹 푸시 구독과 VAPID 설정을 재사용한다. 실패하면 재시도 대기 상태를 보관한다. 기존 `admin-reminder-push` 크론 처리에 OT 알림 재시도를 추가했으며 기존 일정 알림 동작은 유지한다. 화면에서도 알림 재시도를 실행할 수 있다. 구독이 없는 기기에는 푸시를 보낼 수 없고 브라우저 알림 허용·기존 구독 등록이 필요하다. 배포 검증 중 다른 운영진에게 테스트 푸시를 임의로 보내지 않는다.

## 적용 순서와 검증

1. `20261007010721_ot_room_private_invites.sql`: 개별 링크, OT ACL, 알림 및 원자적 등록·투표 RPC.
2. `20261007040802_ot_accounts_and_member_privacy.sql`: 신청 계정, 자동 프로필 생성, 개인 활성화 링크, 호환용 공개 투영. 기존 조회 권한은 이 단계에서 유지한다.
3. `ot-room`, `ot-review`, `vom-access`, `member-account`, `public-events`, `admin-reminder-push`와 `_shared` 파일을 배포한다. `verify_jwt=false` 함수는 본문에서 초대·검증된 JWT·기존 크론 비밀값을 확인한다.
4. GitHub main 및 기존 Vercel 사이트에 호환 프론트엔드를 배포한다.
5. `20261007043043_public_activity_compatibility.sql`로 기존 공개 OPEN MIC 및 주최자 안내를 유지한다.
6. `20261007042424_member_schedule_access.sql`로 개인정보와 스케줄 RLS를 전환하고 운영 사이트에서 공개 화면·로그인 안내·직접 API 차단을 확인한다.

변경된 서버 함수 6개의 타입 검사, 서버 동작 21개, PostgreSQL 마이그레이션·권한 검사 58개, PC/모바일 브라우저 검사 23개를 통과했다. 서버 및 브라우저 검사는 가짜 응답, DB 검사는 실제 마이그레이션을 적용한 로컬 PostgreSQL로 수행한다. 운영 데이터에 테스트 승인·임의 푸시를 실행하지 않는다. 운영 환경 확인 결과는 배포 완료 기록으로 구분한다.

프론트엔드를 롤백하더라도 추가 신청·회원·영상 데이터를 삭제하지 않는다. 현재 배포 전 Edge Function 소스를 별도로 보관하며 보안 전환을 되돌리는 전체 롤백은 데이터와 권한 영향을 검토한다.

```sh
npm ci --prefix tests/runtime
ln -s tests/runtime/node_modules node_modules
npx --yes deno@2.9.6 task check:ot --node-modules-dir=manual
npx --yes deno@2.9.6 test --allow-env=ECE_KEYLOG --node-modules-dir=manual tests/ot_server_test.ts
node tests/ot_database_test.mjs
```
